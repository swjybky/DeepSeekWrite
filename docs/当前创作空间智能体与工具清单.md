# 当前创作空间智能体与工具清单

本文档记录当前 DeepWrite 创作空间中实际启用的智能体、各智能体可调用工具、默认读取范围和写入目标。范围覆盖短篇、长篇与剧本书籍创作空间；素材库、技能库编辑器是独立工作区，不在本文主体范围内。

最后核对时间：2026-07-11。

## 1. 当前创作空间总览

当前 `short`、`long` 和 `script` 都已开放创作空间。短篇与剧本仍使用阶段文本槽位；长篇使用 `long_workspace` 结构化数据，同时投影为阶段文本供读取、搜索、迁移与导出使用。

| 书籍类型 | 左侧可见阶段 | 实际内容槽位 | 当前启用智能体 |
| --- | --- | --- | --- |
| 短篇 `short` | 人物设计、剧情、大纲、正文编写 | `character_design`、`plot_design`、`intro_design`、`plot_refine`、`outline`、`draft` | 人物设计、剧情、大纲、正文专家编写智能体、分节写手智能体 |
| 长篇 `long` | 世界观、人物、剧情、正文、状态账本 | 世界观分类、四类人物档案、全书线/卷/剧情弧/章卡/伏笔、按章三区块正文、状态账本 | 世界观管理、人物管理、剧情管理、正文管理、写手五个主智能体；另有后台状态账本智能体 |
| 剧本 `script` | 人物设计、剧情、大纲、正文编写 | `character_design`、`plot_design`、`plot_refine`、`outline`、`draft` | 人物设计、剧情、大纲、正文专家编写智能体、分节写手智能体 |

注意：

- `剧情` 是合并智能体。短篇下覆盖 `剧情设计 / 导语设计 / 剧情细化` 三个子槽位；剧本下覆盖 `剧情设计 / 剧情细化` 两个子槽位。
- 短篇与剧本的 `draft` 阶段当前进入专家正文模式，不再挂普通阶段聊天。右侧 AI 面板会切到正文专家编写智能体；选中具体小节时显示分节写手语义。长篇 `draft` 则是按章卡调度写手的正文管理智能体。
- 长篇的卷、剧情弧与章卡只在「剧情」阶段创建和删除；「正文」阶段只按同一份剧情结构镜像显示卷/弧/章，不提供另一套创建入口。
- 长篇章卡是正文章节的权威结构源；没有章卡不能启动该章写作。
- 旧的 `draft_review`、`format_conversion` 仍有迁移兼容和部分历史工具代码，但当前左侧不作为独立创作空间智能体展示。

### 1.1 运行时创作上下文

书籍创作空间的系统提示词不再使用 `{{BOOK_TITLE}}`、`{{BOOK_GENRE}}`。`memoryMessageTransform.ts` 会在每次模型请求前插入一条不保存到聊天历史的 user 上下文消息：

- 普通阶段：书名、创作类型、分类、当前阶段；剧情同时标明当前子方向。
- 正文总控：书名、类型、分类和“正文阶段”。
- 分节写手：书名、类型、分类、当前小节序号与标题；短篇导语单独标记。
- 长篇普通阶段：书名、类型、分类和当前结构节点；长篇写手使用单章标题、序号和章卡上下文，状态账本智能体使用待落盘章节上下文。
- 有长期记忆时，书籍记忆和用户记忆附在同一条消息中；没有记忆时仍会提供创作位置。

## 2. 通用工具字典

普通阶段智能体共用以下工具，由短篇和剧本各自的 `stageAgents.ts` 组装。

| 工具名 | 中文标签 | 用途 | 关键约束 |
| --- | --- | --- | --- |
| `read_workspace_content` | 读取工作区内容 | 读取当前书籍某一创作阶段内容，优先读正在显示的编辑框，读不到再回退到已加载/已保存内容。 | 只能读取该智能体读取范围内的阶段；每次只返回一个 `stage_id`。 |
| `search_workspace_text` | 搜索工作区文本 | 在允许读取的创作阶段中搜索关键词或原文片段，返回行列位置和上下文。 | 不返回全文；用于替换失败后定位真实原文。 |
| `query_linked_material_entries` | 查询关联素材条目 | 在当前书籍已关联且当前智能体可读的素材库中列出、检索或读取条目。 | 只有该智能体配置了素材读取范围时才提供；`mode=list` 列出可读条目，`mode=search` 按关键词检索，`mode=read` 优先用 `entry_name` 读取全文；无需传内部 ID，同名时补充 `material_kind` 或 `stage_id` 缩小范围。 |
| `load_skill` | 加载技能 | 从当前书籍绑定、且当前智能体已关联的技能分类库中加载指定技能正文。 | 技能分类由「创作空间设置」按智能体配置；技能正文必须带 `name` 和 `description` front matter。 |
| `write_workspace_editor` | 写入当前文本编辑框 | 将当前智能体对应阶段的正式内容覆盖写入编辑器（人物、剧情、大纲阶段挂载；正文阶段不挂载）。 | 只写创作正文，不写分析报告或过程说明；`target_stage_id` 仅供剧情智能体选择剧情子方向，其它阶段请省略。 |
| `replace_current_stage_text` | 替换当前阶段文本 | 用原文片段定位并替换当前智能体对应阶段文本，支持一次替换多个小片段（含正文阶段）。 | 需要从 `read_workspace_content` 返回正文中复制原文；不依赖行号；`target_stage_id` 仅供剧情智能体选择剧情子方向，其它阶段请省略。 |

正文专家模式额外工具如下。

| 工具名 | 中文标签 | 所属智能体 | 用途 |
| --- | --- | --- | --- |
| `initialize_expert_draft` | 初始化正文 | 正文专家编写智能体 | 根据大纲一次性创建或重建正文小节列表，并同步创建一一对应的人物状态槽位。 |
| `edit_expert_draft_section` | 编辑正文 | 正文专家编写智能体 | 在合并正文中按原文片段修改章节名或正文，用于审阅、润色、去 AI 味和局部后处理。 |
| `start_expert_writing` | 开始写书 | 正文专家编写智能体 | 异步启动后台分节写手，按 `section_ids` 串行写入正文和人物状态。 |
| `write_single_expert_section` | 单章写作 | 正文专家编写智能体 | 异步启动一个分节写手，只编写指定 `section_id`；`user_writing_prompt` 与 `start_expert_writing` 使用同一组织方式。目标小节不存在时提示先初始化。 |
| `read_expert_draft_section` | 读取其它小节 | 分节写手智能体 | 读取专家正文模式中指定小节的正文和人物状态，优先读当前编辑框，读不到再读已保存内容。 |
| `write_section_body` | 写入正文 | 分节写手智能体 | 覆盖当前正在编写的小节正文。 |
| `replace_section_body_text` | 替换正文片段 | 分节写手智能体 | 修改当前小节已有正文，不覆盖其它内容。 |
| `write_character_state` | 写入人物状态 | 分节写手智能体 | 覆盖当前小节对应的人物状态。 |
| `replace_character_state_text` | 替换人物状态片段 | 分节写手智能体 | 修改当前小节已有的人物状态。 |

## 3. 短篇创作空间智能体

短篇工作台类型：`short`。

剧情父阶段包含三个写入目标：

| 子槽位 | 中文含义 |
| --- | --- |
| `plot_design` | 剧情设计 |
| `intro_design` | 导语设计 |
| `plot_refine` | 剧情细化 |

### 3.1 智能体清单

| Agent ID | 智能体 | 描述 | 支撑工具 | 默认可读工作区 | 默认可读素材 |
| --- | --- | --- | --- | --- | --- |
| `character_design` | 人物设计 | 协助用户编写、修改人物设计。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 人物设计 `character_design` | 人设素材 `character` |
| `plot_design` | 剧情 | 统一处理剧情设计、导语设计、剧情细化；可统筹三个方向，也可写入指定剧情子槽位。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 人物设计 `character_design`、剧情设计 `plot_design`、导语设计 `intro_design`、剧情细化 `plot_refine` | 人设素材 `character`、导语素材 `intro`、梗素材 `gimmick`、剧情设计素材 `pacing`、剧情细化素材 `plot_refine` |
| `outline` | 大纲 | 将剧情和人设内容整理成大纲，或按用户要求重新创作大纲；成品要求包含章节数量、每章字数和详细剧情。 | `read_workspace_content`、`search_workspace_text`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 剧情设计 `plot_design`、导语设计 `intro_design`、剧情细化 `plot_refine`、大纲 `outline`、人物设计 `character_design` | 无 |
| `expert_draft_coordinator` | 正文专家编写智能体 | 正文编写阶段总控。负责初始化正文小节和人物状态、启动单节或全部写作，并处理审阅、修改、去 AI 味和格式整理；用户明确要求开始时会在同一轮初始化并启动。 | `read_workspace_content`、`search_workspace_text`、`load_skill`、`initialize_expert_draft`、`edit_expert_draft_section`、`start_expert_writing`、`write_single_expert_section` | 大纲 `outline`、正文编写 `draft` | 无 |
| `expert_section_writer` | 分节写手智能体 | 后台串行编写单个小节。完成当前小节正文后，必须同步写入该小节结束时的人物状态。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`read_expert_draft_section`、`write_section_body`、`write_character_state` | 大纲 `outline`、剧情细化 `plot_refine`、正文编写 `draft` | 正文片段 `draft_excerpt` |

### 3.2 短篇写入规则

- 写入工具默认操作当前智能体对应阶段；人物、大纲等普通阶段无需传 `target_stage_id`。
- 剧情智能体处于父阶段 `plot_design` 时，`target_stage_id` 仅供选择剧情子方向（`plot_design`、`intro_design` 或 `plot_refine`）；省略时写入当前选中的剧情子方向。
- 正文阶段不挂载 `write_workspace_editor`，仅提供 `replace_current_stage_text` 做局部替换。
- 正文专家总控不直接调用普通阶段写入工具，而是通过正文列表、人物状态列表和后台写作工具改变专家正文结构。
- 短篇 `start_expert_writing` 默认跳过 `intro` 导语小节，从第一节开始串行写作。
- 短篇 `write_single_expert_section` 可单独写一个已初始化小节，包括用户显式指定的导语；目标 `section_id` 不存在时会提醒先初始化正文列表。

## 4. 剧本创作空间智能体

剧本工作台类型：`script`。

剧情父阶段包含两个写入目标：

| 子槽位 | 中文含义 |
| --- | --- |
| `plot_design` | 剧情设计，包含整体故事走向、核心冲突、关键节点、真实时间线、开篇钩子 |
| `plot_refine` | 剧情细化，包含场景链、节拍、信息投放与人物选择 |

### 4.1 智能体清单

| Agent ID | 智能体 | 描述 | 支撑工具 | 默认可读工作区 | 默认可读素材 |
| --- | --- | --- | --- | --- | --- |
| `character_design` | 人物设计 | 协助用户编写、修改剧本人物设计。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 人物设计 `character_design`、剧情设计 `plot_design`、剧情细化 `plot_refine` | 人设素材 `character` |
| `plot_design` | 剧情 | 统一处理剧本剧情设计和剧情细化；可写入当前剧情子方向，也可指定写入目标。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 人物设计 `character_design`、剧情设计 `plot_design`、剧情细化 `plot_refine` | 人设素材 `character`、导语素材 `intro`、梗素材 `gimmick`、剧情设计素材 `pacing`、剧情细化素材 `plot_refine` |
| `outline` | 大纲 | 整合剧本剧情和人设，形成章节/场次级大纲；若是创作大纲则重新创作。 | `read_workspace_content`、`search_workspace_text`、`load_skill`、`write_workspace_editor`、`replace_current_stage_text` | 大纲 `outline`、人物设计 `character_design`、剧情设计 `plot_design`、剧情细化 `plot_refine` | 无 |
| `expert_draft_coordinator` | 正文专家编写智能体 | 剧本正文编写阶段总控。负责初始化小节和人物状态、启动单节或全部写作，并处理审阅、修改、去 AI 味和格式整理；用户明确要求开始时会在同一轮初始化并启动。 | `read_workspace_content`、`search_workspace_text`、`load_skill`、`initialize_expert_draft`、`edit_expert_draft_section`、`start_expert_writing`、`write_single_expert_section` | 大纲 `outline`、正文编写 `draft` | 无 |
| `expert_section_writer` | 分节写手智能体 | 后台串行编写单个剧本小节。产出必须符合剧本格式，并写回正文与人物状态。 | `read_workspace_content`、`search_workspace_text`、`search_linked_materials`、`read_linked_material_content`、`load_skill`、`read_expert_draft_section`、`write_section_body`、`write_character_state` | 大纲 `outline`、正文编写 `draft` | 正文片段 `draft_excerpt` |

### 4.2 剧本写入规则

- 写入工具默认操作当前智能体对应阶段；人物、大纲等普通阶段无需传 `target_stage_id`。
- 剧情智能体处于父阶段 `plot_design` 时，`target_stage_id` 仅供选择剧情子方向（`plot_design` 或 `plot_refine`）；省略时写入当前选中的剧情子方向。
- 正文阶段不挂载 `write_workspace_editor`，仅提供 `replace_current_stage_text` 做局部替换。
- 剧本没有独立 `intro_design` 可见槽位；开篇钩子并入剧情设计。
- 剧本 `start_expert_writing` 默认会写全部正文小节，不跳过第一节。
- 剧本 `write_single_expert_section` 可单独写一个已初始化小节；目标 `section_id` 不存在时会提醒先初始化正文列表。
- 剧本分节写手提示词要求正文产出严格遵守剧本格式。

## 5. 长篇创作空间

长篇工作台类型：`long`。它不沿用短篇的单块文本模型，而是以 `Book.long_workspace` 中的 schema v2 结构化数据为权威数据源。`stages` 保留为它的文本投影，用于兼容阶段读取、搜索、旧数据迁移和导出；结构化编辑时以 `long_workspace` 为准。

### 5.1 五个可见阶段与结构化数据

| 可见根阶段 | Root ID | 实际结构 |
| --- | --- | --- |
| 世界观 | `worldbuilding` | 默认规则、势力、地理、历史、术语、境界、物品七个分类；分类可新增、重命名、删除，每类独立选择列表或文本格式。 |
| 人物 | `character_design` | 固定为主角、主要配角、次要配角、路人四组；每组下是独立人物记录。 |
| 剧情 | `plot_design` | 全书线（总纲）、分卷（卷纲）、剧情弧（时间线安排）、章卡、伏笔。卷 -> 剧情弧 -> 章卡是权威层级。 |
| 正文 | `draft` | 按章卡 `stage_id` 存储正文、人物状态、交接注意文档三个区块，以及落盘标志、时间和 `commit_id`。 |
| 状态账本 | `continuity_ledger` | 全文落盘进度、章节时间线、人物实时状态、势力状态、境界状态、伏笔状态与连续性记录。 |

长篇默认播种第一卷、第一剧情弧和第一章卡。后续所有卷、剧情弧和章卡都在「剧情」阶段管理。删除卷会级联删除它的剧情弧、章卡和对应正文；删除剧情弧会级联删除它的章卡和对应正文。

「正文」左侧树只读地镜像「剧情」的卷 -> 剧情弧 -> 章卡层级：剧情阶段新建或删除后会同步变化，正文阶段不提供新建卷、弧或章的按钮。

### 5.2 五个主智能体与后台状态账本智能体

| Agent ID | 智能体 | 实际职责 | 关键工具 |
| --- | --- | --- | --- |
| `worldbuilding` | 世界观管理智能体 | 查询与维护可扩展的世界观分类，严格区分列表格式与文本格式的读取方式。 | `list_worldbuilding`、`query_worldbuilding`、`query_worldbuilding_item`、`query_worldbuilding_text` |
| `character_design` | 人物管理智能体 | 维护四组人物列表和每人四个页签；落盘前不把推测写成已发生状态。 | `list_long_characters`、`query_long_character` |
| `plot_design` | 剧情管理智能体 | 管理全书线、卷纲、剧情弧时间线、章卡和伏笔；为正文提供权威层级和章卡。 | `query_long_plot_structure`、`query_long_chapter_card` |
| `draft` | 正文管理智能体 | 根据章卡顺序分析下一处应写、补齐或落盘的章节，并调度写手。它不提供整本书自动写作。 | `find_next_long_chapter`、`query_long_chapter_card`、`start_long_writing` |
| `expert_section_writer` | 写手智能体 | 被正文管理智能体按单章调用；一次只处理一张章卡，必须写回正文、章末人物状态和交接注意文档。 | `read_current_chapter_card`、`write_long_chapter_body`、`write_long_chapter_character_state`、`write_long_chapter_handoff` |
| `continuity_ledger` | 状态账本智能体（后台） | 用户点击「落盘」后运行，从已写章节提取已发生事实，提交人物、时间线、势力、境界、伏笔和连续性变化。 | 专用落盘运行仅挂载 `commit_long_chapter_state` |

前五个是长篇创作主链路的智能体。`continuity_ledger` 是独立可配置的后台智能体；「状态账本」同时作为第五个可见阶段展示它的落盘结果。长篇普通 AI 面板会按读取范围挂载 `read_workspace_content`、`search_workspace_text`、`query_linked_material_entries`、`load_skill` 与结构化查询工具；结构化查询会对所需根阶段再做权限校验。世界观、人物和剧情智能体只通过各自的结构化变更工具写入 `long_workspace`，不挂载旧的平面 `write_workspace_editor` / `replace_current_stage_text`，避免投影文本与权威结构脱节。

正文管理智能体只有查询与 `start_long_writing`，不直接改写正文三区块。可见的状态账本节点没有普通写入工具；真正的状态变更只能在用户点击「落盘」后，由后台智能体调用 `commit_long_chapter_state` 和后端原子接口完成。

### 5.3 世界观的列表格式与文本格式

书籍顶部在「记忆管理」左侧提供「世界观格式管理」按钮。弹窗中可新增、重命名、删除分类，也可为每个分类独立切换格式。切换时会保留原数据：列表首次切到文本时会生成文本，空列表从文本切回时会以原文本播种一条「原文本内容」。

| 格式 | 编辑器数据 | 对智能体提供的专用查询 |
| --- | --- | --- |
| 列表格式 | 一份「所有分类列表概述」，加若干条目；每条包含名称、描述、详细介绍。 | `query_worldbuilding` 返回分类概述以及全部条目的名称/描述索引；`query_worldbuilding_item` 再按名称或 ID 读取单条名称、描述和详细介绍。 |
| 文本格式 | 该分类的所有信息保存在一个连续文本框。 | `query_worldbuilding_text` 直接返回该分类全文。 |

`list_worldbuilding` 先列出所有分类、当前格式和规模。三个详细查询工具会校验格式：用列表工具读文本分类，或用文本工具读列表分类，都会返回明确的改用工具提示。

文本格式按非空白字符计数。超过 30000 字时，字数左侧显示红色提示：「字数过多，请转成列表格式，提高智能体性能。」

### 5.4 人物四组与四个页签

人物阶段的分组固定为 `protagonists` 主角、`major_supporting` 主要配角、`minor_supporting` 次要配角、`passersby` 路人。每组都是可新增、选择、重命名和删除的人物列表。单个人物右侧固定为四个页签：

1. `core_profile` 核心人设。
2. `relationships` 人物关系，同时承载初始关系和已发生的关系变化。
3. `current_state` 当前状态，记录当前章节/时间点、地点、已知信息、持有物、伤病、立场与后续出场信息。
4. `history` 历史状态变化。

`list_long_characters` 按固定分组列出人名和 ID；`query_long_character` 按人名或 ID 一次返回该人物的四个页签全文。章节落盘时，后台状态账本智能体的 `character_updates` 会同步到这里的人物关系、当前状态和历史状态变化。

### 5.5 剧情建立结构，正文同步显示

- `plot_design.book_line` 是单一全书线文本框。
- `plot_design.volumes` 是分卷列表，每卷包含卷名和卷纲。
- `plot_design.story_arcs` 先选卷，再管理该卷下的剧情弧列表；单个剧情弧右侧编辑时间线安排。
- `plot_design.chapter_cards` 是卷 -> 剧情弧 -> 章卡三层选择结构。章卡包含章名、章纲、世界观强约束和出场人物。
- `plot_design.foreshadowing` 是伏笔列表，单条包含名称、描述、内容和状态（未回收/推进中/已回收）。

`query_long_plot_structure` 按 `all`、`book_line`、`volumes`、`arcs` 或 `foreshadowing` 查询剧情结构；`query_long_chapter_card` 按章名或 `stage_id` 返回具体章卡。

每张章卡创建后会同步生成对应的章节三区块数据，「正文」树中即时显示同一个章节。因此正文阶段不建第二套卷、弧、章结构，也不允许跳过章卡直接生成新章。

### 5.6 单章/剧情弧/分卷写作与顺序落盘

`find_next_long_chapter` 按章卡顺序查找最早尚未完成的章节，区分「正文为空，需要写作」、「三区块未齐，需要补齐」、「三区块已齐，需要落盘」三种状态。

`start_long_writing` 的 `scope` 仅接受：

- `chapter` + `chapter_stage_id`：写指定单章。
- `arc` + `arc_id`：按章卡顺序串行编写指定剧情弧。
- `volume` + `volume_id`：按章卡顺序串行编写指定卷。

接口没有 `book` 选项，整本书自动写作被明确禁止。剧情弧和卷范围内仍由写手智能体每次处理一章，串行进入下一章，不并发写多章。

每章右侧编辑器固定有三个页签：`body` 正文、`character_state` 人物状态、`handoff` 交接注意文档。写手运行时必须依次调用三个专用写回工具；首轮未写齐时会再次要求补齐，任一区块仍为空则停止该批次。

用户点击本章「落盘」后，落盘链路先保存当前工作区，再运行后台状态账本智能体。落盘的前置校验是：

1. 当前章有对应章卡。
2. 正文、人物状态、交接注意文档三个区块均非空。
3. 按章卡顺序位于当前章之前的所有章节都已落盘。任一前章未落盘时拒绝跳章。
4. 当前章尚未落盘，避免重复追加账本。

`commit_long_chapter_state` 将时间线、势力、境界、伏笔、连续性、人物和伏笔更新提交给后端 `commit_long_chapter`。后端再次校验后以同一 `commit_id` 标记章节已落盘、推进 `committed_through`、更新人物关系/当前状态/历史变化，并追加时间线、势力、境界、伏笔与连续性账本。落盘成功的章节在正文树标记「已落盘」，三个页签转为只读，避免正文与账本状态再次分叉。

| `query_worldbuilding` | 读取列表分类的总概述和名称/描述索引。 | 只接受列表格式。 |

### 5.8 长篇创作空间设置

「创作空间设置」已有独立「长篇」页签，左侧分为：

- 「前置阶段」：世界观管理智能体、人物管理智能体、剧情管理智能体。
- 「正文编写」：正文管理智能体、写手智能体。
- 「后台流转」：状态账本智能体（后台）。

每个长篇智能体都可单独编辑和恢复系统提示词，并单独配置：

- 创作空间阶段读取范围。
- 素材库读取范围：人设、梗、剧情、正文、其他素材库。
- 技能库加载范围：通用、剧情设计、文风写作、其他技能库。

默认长篇提示词与读取范围位于 `app/prompt_defaults/long/shared/`。系统提示词停止输入 1 秒后自动保存，持续输入最长 5 秒落盘一次；读取范围在勾选变化后立即进入保存队列。用户覆盖与长篇读取范围保存到本地数据目录，运行时优先使用用户配置。

## 6. 技能分类加载关系

`load_skill` 只读取当前书籍已绑定、且当前智能体在「创作空间设置」中关联的技能分类库。新版分类绑定不再按当前创作阶段过滤技能库内部的旧阶段槽位，而是汇总所选分类库中的全部有效技能条目。`stage_id` 仅用于校验工具属于当前智能体。技能正文开头必须包含 front matter：

```markdown
---
name: 技能名
description: 技能描述
---
```

短篇与剧本的默认关联分类相同：

| 智能体 | 默认关联技能分类 |
| --- | --- |
| `character_design` | 通用技能库、剧情设计技能库、其他技能库 |
| `plot_design` | 通用技能库、剧情设计技能库、其他技能库 |
| `outline` | 通用技能库、剧情设计技能库、其他技能库 |
| `expert_draft_coordinator` | 通用技能库、文风写作技能库、其他技能库 |
| `expert_section_writer` | 通用技能库、文风写作技能库、其他技能库 |

长篇的默认关联分类如下：

| 智能体 | 默认关联技能分类 |
| --- | --- |
| `worldbuilding` | 通用技能库、剧情设计技能库、其他技能库 |
| `character_design` | 通用技能库、剧情设计技能库、其他技能库 |
| `plot_design` | 通用技能库、剧情设计技能库、其他技能库 |
| `draft` | 通用技能库、剧情设计技能库、文风写作技能库、其他技能库 |
| `expert_section_writer` | 通用技能库、文风写作技能库、其他技能库 |
| `continuity_ledger` | 无 |

旧书籍如果只有单个 `linked_skill_id`，仍按旧阶段槽位加载，以兼容历史数据；新版 `linked_skill_ids_by_kind` 使用上述分类配置。

## 7. 读取范围与配置来源

创作空间读取范围和技能分类关联有两层来源：

1. 默认读取范围分别来自 `app/prompt_defaults/short/shared/read_access.json`、`app/prompt_defaults/long/shared/read_access.json` 和 `app/prompt_defaults/script/shared/read_access.json`。
2. 用户在「创作空间设置」页修改后，会保存到本地 `.data/preferences.json`，运行时优先读取该配置，再由前端按当前书籍类型归一化。

归一化规则：

- 短篇与剧本保留 5 个 Agent ID：`character_design`、`plot_design`、`outline`、`expert_draft_coordinator`、`expert_section_writer`。旧的 `intro_design`、`plot_refine` 读取配置会合并到 `plot_design`。
- 长篇保留 6 个可配置 Agent ID：`worldbuilding`、`character_design`、`plot_design`、`draft`、`expert_section_writer`、`continuity_ledger`。其中前五个是主智能体，`continuity_ledger` 是后台落盘智能体。
- 每个智能体必须能读取自己的必需阶段；长篇的动态世界观分类和动态正文章节会按所属根阶段纳入读取范围。
- `workspace` 和 `material` 配置影响读取类工具和提示词可见上下文；`skill` 配置决定系统提示词、`load_skill` 和 `/` 技能快捷选择可见的技能分类。
- 上述配置不改变写入工具本身的存在。
