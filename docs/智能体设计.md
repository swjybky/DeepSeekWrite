# Deep Write 智能体设计文档

本文档说明项目中 AI 智能体的整体架构，包括创作空间（书籍工作台）、素材库、以及专家模式（多智能体写作）的设计与实现位置。

---

## 一、整体架构概览

项目采用 **[Pi](https://github.com/badlogic/pi) 框架**（`@mariozechner/pi-agent-core`）构建智能体，所有智能体均为前端 `Agent` 实例，通过 `ChatPanel`（`pi-web-ui`）渲染对话界面。

```
┌─────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────┤

│  用户覆盖    : 用户数据目录/.data/prompt_overrides/          │

│  前端降级    : web/src/prompt/embeddedDefaults.ts           │
```

## 二、创作空间 vs 素材库：是否区分？

**做了明确区分**。核心开关是 `WorkspaceAiChat` 组件的 `workspaceType` 属性（`'book'` / `'material'`），两条管线在三层面隔离：

| 维度 | 创作空间（书籍） | 素材库 |
|------|----------------|--------|
| **阶段定义** | 8 阶段：`character_design` → `format_conversion` | 6 阶段：`character` → `draft_excerpt` |
| **提示词目录** | `app/prompt_defaults/short/shared/` | `app/prompt_defaults/material/{long,short_*}/` |
| **工具集** | 按阶段动态变化（见第 4 节） | 固定：读取其它素材 + 写入编辑区 |
| **配置入口** | 首页「创作空间」卡片 →「设置」 | 素材编辑器内保留提示词编辑 |
| **会话隔离** | 每阶段独立会话 | 每阶段独立会话 |

**统一分发入口**：`web/src/pi/workspaceStageAgents.ts`
- 根据 `workspaceType` 决定调用 `buildShortWorkspaceAdditionalTools()` 还是 `buildMaterialWorkspaceAdditionalTools()`；`promptKind` 仅用于素材库。

## 三、提示词在哪里给？如何维护？

### 3.1 普通工作台（创作空间 + 素材库共用同一套后端管线）

#### 物理位置

- **默认模板**：`app/prompt_defaults/` 下的 `.txt` 文件
  - 创作空间共享模板：`app/prompt_defaults/short/shared/*.txt`
  - 素材库：`app/prompt_defaults/material/{long,short_*}/*.txt`

- **用户覆盖**：用户数据目录下 `.data/prompt_overrides/` 的同路径文件（优先级高于默认模板）
  - 创作空间共享覆盖：`.data/prompt_overrides/short/shared/*.txt`
  - 旧 `short/qinggan/` 覆盖首次加载时会复制到共享目录，之后旧分类目录不再生效

#### 运行时加载链路

1. 前端 `bridge.ts` → `getWorkspaceSystemPrompt()` / `getMaterialSystemPrompt()`
2. 调用后端 Python `app/prompt_store.py`
3. `prompt_store.py` 按 **覆盖优先** 读取磁盘模板
4. 创作空间直接返回原始 system prompt；素材库仍按自身占位符协议渲染
5. system prompt 注入 `Agent`；每次请求前，前端另行插入包含书名、类型、分类、当前位置和长期记忆的 user 上下文消息

创作空间不再支持 `{{BOOK_TITLE}}`、`{{BOOK_GENRE}}` 或其它动态占位符。阶段正文、素材和技能通过受读取范围约束的工具按需获取。

#### 浏览器开发模式降级

`web/src/prompt/embeddedDefaults.ts` 用 `import.meta.glob` 把磁盘模板打包进前端，供 `npm run dev` 时无需 Python 后端也能跑。

#### 用户修改入口

首页「创作空间」卡片中的 **「设置」** 按钮进入 `/workspace-settings`。设置页分别管理短篇与剧本的 5 个智能体：人物、剧情、大纲、正文专家总控和分节写手。

### 3.2 专家模式提示词

专家模式系统提示词同样走共享磁盘模板管线：

- `app/prompt_defaults/short/shared/expert_draft_coordinator.txt` —— 总控智能体系统提示词
- `app/prompt_defaults/short/shared/expert_section_writer.txt` —— 小节编写智能体系统提示词
- `web/src/workspaces/short/expertDraft/prompts.ts` —— 给原始模板附加可读素材/技能说明，并生成每小节动态任务消息
- `web/src/pi/memoryMessageTransform.ts` —— 生成正文总控或当前单独小节的运行时 user 上下文

专家总控和后台小节编写智能体各自拥有独立读取范围；读取工具只暴露已勾选的普通创作阶段。专家正文、小节和人物状态由专家工具读取。

## 四、工具在哪里注册？怎么做阶段区分？

### 4.1 工具定义层（三段式架构）

| 文件 | 职责 |
|------|------|
| `web/src/workspaces/shared/piToolkit.ts` | **通用工具基座**：提供 `defineTool` / `textBlock` / 摘录等基础设施。 |
| `web/src/workspaces/short/stageAgents.ts` | **创作空间工具编排**：按当前 `stageId` 动态组装工具列表。 |
| `web/src/workspaces/material/materialStageAgents.ts` | **素材库工具编排**：固定提供 `read_material_content` + `write_material_editor`。 |
| `web/src/pi/workspaceStageAgents.ts` | **统一分发入口**：根据 `workspaceType` 决定走素材库还是短篇路径。 |

### 4.2 创作空间各阶段工具配置

`buildShortWorkspaceAdditionalTools()` 在 `stageAgents.ts` 中按阶段返回不同工具集：

| 阶段 | 可用工具 |
|------|---------|
| `character_design` / `plot_design` / `intro_design` / `plot_refine` / `outline` / `draft_review` | 按配置提供 `read_workspace_content`、`read_linked_material_content`，并提供 `write_workspace_editor` |
| `draft` | 按配置提供读取工具，并提供 `replace_draft_editor_text` |
| `format_conversion` | 按配置提供读取工具，并提供 `copy_stage_to_format_conversion`、`global_text_replace` |

读取范围只控制读取工具和阶段摘录；正文替换、格式转换复制、全局替换等阶段专属工具不受影响。

### 4.3 素材库工具配置

`buildMaterialWorkspaceAdditionalTools()` 在 `materialStageAgents.ts` 中固定返回：

- `read_material_content` —— 读取当前素材其它阶段已保存内容
- `write_material_editor` —— 把内容写入中间编辑区（replace / append）

### 4.4 注册时机

在 `WorkspaceAiChat.tsx` 中：

```ts
await chatPanel.setAgent(agent, {
  onApiKeyRequired: async (provider: string) => ApiKeyPromptDialog.prompt(provider),
  toolsFactory: ctxTools,  // ← 工具工厂函数，每次阶段更新时重新计算
})
```

`toolsFactory` 是一个工厂函数，当 `stageId`、`stageBody`、`linkedMaterial` 等依赖变化时，Pi 框架会重新调用它获取最新工具列表。

## 五、专家模式（多智能体写作）设计

专家模式只在 **正文编写（`draft`）阶段** 生效，采用 **Coordinator + 多个 Section Writer 的串行多智能体架构**。

### 5.1 文件位置与角色

| 文件 | 角色 |
|------|------|
| `web/src/workspaces/short/expertDraft/ExpertDraftAiChat.tsx` | **Coordinator 智能体 UI 壳**：挂载总控 Agent，管理聊天面板的显示与切换。 |
| `web/src/workspaces/short/expertDraft/coordinatorTools.ts` | **Coordinator 工具**：`create_draft_sections`（创建正文列表）、`create_character_state_sections`（创建人物状态列表）、`start_expert_writing`（启动多章后台写作）、`write_single_expert_section`（单章后台写作）。 |
| `web/src/workspaces/short/expertDraft/sectionWriter.ts` | **Section Writer 执行引擎**：串行创建/运行每个小节的独立 Agent。 |
| `web/src/workspaces/short/expertDraft/prompts.ts` | **专家模式提示词**：总控系统提示词 + 小节编写系统提示词 + 动态用户提示词。 |
| `web/src/workspaces/short/expertDraft/ExpertDraftEditor.tsx` | **左侧编辑器**：显示小节列表 + 人物状态列表的可视化界面。 |

### 5.2 设计原理

#### 总控智能体（Coordinator）

- **系统提示词**：`buildExpertDraftCoordinatorSystemPrompt()`
- **任务范围**：
  1. 根据已有大纲和设计内容，初始化专家模式的「正文小节列表」与「人物状态列表」。
  2. 用户明确要求开始正文时，缺少结构则先初始化，并在同一轮调用 `start_expert_writing`；只写一个已初始化章节时调用 `write_single_expert_section`。
- **可读上下文**：当前专家正文/人物状态列表始终可读；普通创作阶段与关联素材通过总控智能体独立读取范围控制。
- **约束**：必须使用工具修改左侧编辑器，不要只在聊天里输出列表；不要调用普通模式工具。

#### 后台小节编写智能体（Section Writer）

- **系统提示词**：`buildSectionWriterSystemPrompt()`
- **运行机制**：
- 一次后台任务创建一个分节 `Agent`，每进入新小节都会刷新系统提示词、工具和运行时小节上下文
- **严格串行**执行：写完第 N 节，再写第 N+1 节
- **写入工具**：
  - `write_section_body` —— 覆盖当前小节正文框
  - `write_character_state` —— 覆盖当前小节人物状态框
- **读取工具**：按后台小节编写智能体的独立读取范围提供 `read_workspace_content` / `read_linked_material_content`
- **运行时 user 上下文**：注入当前书名、类型、分类以及当前小节序号和标题
- **动态任务消息**：`buildSectionWriterUserPrompt()` 注入小节内部 ID、字数要求、最近三个前置小节 ID、用户写作偏好和写回标准；正文与人物状态仍通过工具读取

#### UI 切换逻辑

- 平时右侧显示 **Coordinator** 聊天面板
- 当 `start_expert_writing` 或 `write_single_expert_section` 启动后，每写一个小节，右侧聊天面板**临时切换**到该小节的 **Section Writer Agent**
- 写完一小节后自动切回 Coordinator，直到所有小节完成

### 5.3 状态流转

```
[Coordinator 初始化列表]
         ↓
[用户确认 / AI 调用 start_expert_writing 或 write_single_expert_section]
         ↓
[创建 AbortController]
         ↓
[for 每个 sectionId] ──→ [创建 Section Writer Agent]
                            ↓
                     [运行 Agent：写正文 + 写人物状态]
                            ↓
                     [Agent 结束，切回 Coordinator]
                            ↓
                     [继续下一个 sectionId]
         ↓
[全部完成 / 用户中断] ──→ [running=false, active_section_id='']
```
