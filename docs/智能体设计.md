# Write Claw 智能体设计文档

本文档说明项目中 AI 智能体的整体架构，包括创作空间（书籍工作台）、素材库、以及专家模式（多智能体写作）的设计与实现位置。

---

## 一、整体架构概览

项目采用 **[Pi](https://github.com/badlogic/pi) 框架**（`@mariozechner/pi-agent-core`）构建智能体，所有智能体均为前端 `Agent` 实例，通过 `ChatPanel`（`pi-web-ui`）渲染对话界面。

```
┌─────────────────────────────────────────────────────────────┐
│                    提示词维护层                              │
├─────────────────────────────────────────────────────────────┤
│  磁盘模板    : app/prompt_defaults/                         │
│  用户覆盖    : .data/prompt_overrides/                      │
│  后端渲染    : app/prompt_store.py（占位符替换）             │
│  前端降级    : web/src/prompt/embeddedDefaults.ts           │
│  专家模式    : web/src/workspaces/short/expertDraft/        │
│                prompts.ts（代码硬编码）                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    工具注册层                                │
├─────────────────────────────────────────────────────────────┤
│  通用工具    : web/src/workspaces/shared/piToolkit.ts       │
│  短篇工具    : web/src/workspaces/short/stageAgents.ts      │
│  素材工具    : web/src/workspaces/material/                 │

│                → ChatPanel.setAgent()                       │
└─────────────────────────────────────────────────────────────┘
                              ↓

│                    智能体实例层                              │
├─────────────────────────────────────────────────────────────┤
│  普通模式    : WorkspaceAiChat.tsx（单 Agent，阶段隔离）     │
│  素材库      : WorkspaceAiChat.tsx（workspaceType='material'）│
```

## 二、创作空间 vs 素材库：是否区分？

**做了明确区分**。核心开关是 `WorkspaceAiChat` 组件的 `workspaceType` 属性（`'book'` / `'material'`），两条管线在三层面隔离：

| 维度 | 创作空间（书籍） | 素材库 |
|------|----------------|--------|
| **阶段定义** | 8 阶段：`character_design` → `format_conversion` | 4 阶段：`character` / `intro` / `gimmick` / `pacing` |
| **提示词目录** | `app/prompt_defaults/short/{shiqing,qinggan}/` | `app/prompt_defaults/material/{long,short_shiqing,short_qinggan}/` |
| **工具集** | 按阶段动态变化（见第 4 节） | 固定：读取其它素材 + 写入编辑区 |
| **UI 差异** | 有「写入正文」抽取按钮 | 无抽取按钮 |
| **会话隔离** | 每阶段独立会话 | 每阶段独立会话 |

**统一分发入口**：`web/src/pi/workspaceStageAgents.ts`
- 根据 `promptKind` 前缀是否以 `material_` 开头，决定调用 `buildShortWorkspaceAdditionalTools()` 还是 `buildMaterialWorkspaceAdditionalTools()`。

## 三、提示词在哪里给？如何维护？

### 3.1 普通工作台（创作空间 + 素材库共用同一套后端管线）

#### 物理位置

- **默认模板**：`app/prompt_defaults/` 下的 `.txt` 文件
  - 短篇世情：`app/prompt_defaults/short/shiqing/*.txt`
  - 短篇追妻：`app/prompt_defaults/short/qinggan/*.txt`
  - 素材库：`app/prompt_defaults/material/{long,short_shiqing,short_qinggan}/*.txt`

- **用户覆盖**：`.data/prompt_overrides/` 下同路径文件（优先级高于默认模板）

#### 运行时加载链路

1. 前端 `bridge.ts` → `getWorkspaceSystemPrompt()` / `getMaterialSystemPrompt()`
2. 调用后端 Python `app/prompt_store.py`
3. `prompt_store.py` 按 **覆盖优先** 读取磁盘模板
4. 后端做占位符替换：`{{BOOK_TITLE}}`、`{{BOOK_LINE}}`、`{{STAGE_BODY}}`、`{{OTHER_STAGES_EXCERPT}}`
5. 渲染后的完整 system prompt 返回给前端，注入 `Agent` 实例

#### 浏览器开发模式降级

`web/src/prompt/embeddedDefaults.ts` 用 `import.meta.glob` 把磁盘模板打包进前端，供 `npm run dev` 时无需 Python 后端也能跑。

#### 用户修改入口

工作台右侧 AI 面板顶部 **「编辑提示词」** 按钮 → 修改后保存到 `.data/prompt_overrides/short/{shiqing,qinggan}/{stage_id}.txt`，即时生效。

### 3.2 专家模式提示词

**全部写死在代码里**，不走磁盘模板管线：

- `web/src/workspaces/short/expertDraft/prompts.ts`：
  - `buildExpertDraftCoordinatorSystemPrompt()` —— 总控智能体系统提示词
  - `buildSectionWriterSystemPrompt()` —— 小节编写智能体系统提示词
  - `buildSectionWriterUserPrompt()` —— 每小节动态用户提示词（注入前序小节、人物状态、大纲等上下文）

> 这意味着专家模式的提示词**目前不支持用户在 UI 上编辑覆盖**，需改代码才能调整。

## 四、工具在哪里注册？怎么做阶段区分？

### 4.1 工具定义层（三段式架构）

| 文件 | 职责 |
|------|------|
| `web/src/workspaces/shared/piToolkit.ts` | **通用工具基座**：定义 `narrative_template`、`scene_structure_hint`、`causality_question_cards`、`outline_hierarchy_scan`、`chapter_placeholder_grid`、`manuscript_metrics`、`editorial_rubric`、`line_level_quick_scan` 等 8 个跨阶段通用工具，以及 `defineTool` / `textBlock` 等基础设施。 |
| `web/src/workspaces/short/stageAgents.ts` | **创作空间工具编排**：按当前 `stageId` 动态组装工具列表。 |
| `web/src/workspaces/material/materialStageAgents.ts` | **素材库工具编排**：固定提供 `read_material_content` + `write_material_editor`。 |
| `web/src/pi/workspaceStageAgents.ts` | **统一分发入口**：根据 `promptKind` 前缀决定走素材库还是短篇路径。 |

### 4.2 创作空间各阶段工具配置

`buildShortWorkspaceAdditionalTools()` 在 `stageAgents.ts` 中按阶段返回不同工具集：

| 阶段 | 可用工具 |
|------|---------|
| `character_design` / `intro_design` / `plot_design` | `read_workspace_content`（读取任意阶段已保存内容）<br>`read_linked_material_content`（读取关联素材库） |
| `plot_refine` | `scene_structure_hint`（场次结构速描）<br>`causality_question_cards`（因果链追问卡）<br>`read_workspace_content` |
| `outline` | `outline_hierarchy_scan`（大纲层级扫描）<br>`chapter_placeholder_grid`（分章占位格）<br>`editorial_rubric`（编审量表）<br>`read_workspace_content` |
| `draft` | `manuscript_metrics`（稿件度量）<br>`read_workspace_content` |
| `draft_review` | `editorial_rubric`（编审量表）<br>`line_level_quick_scan`（行文噪声快扫）<br>`manuscript_metrics`（稿件度量）<br>`read_workspace_content` |
| `format_conversion` | `read_workspace_content` |

### 4.3 素材库工具配置

`buildMaterialWorkspaceAdditionalTools()` 在 `materialStageAgents.ts` 中固定返回：

- `read_material_content` —— 读取当前素材其它阶段已保存内容
- `write_material_editor` —— 把内容写入中间编辑区（replace / append）

### 4.4 注册时机

在 `WorkspaceAiChat.tsx` 中：

```ts
await chatPanel.setAgent(agent, {
  onApiKeyRequired: async (provider: string) => ApiKeyPromptDialog.prompt(provider),
  toolsFactory: ctxTools,  // ← 工具工厂函数，每次阶段更新时重新计算
})
```

`toolsFactory` 是一个工厂函数，当 `stageId`、`stageBody`、`linkedMaterial` 等依赖变化时，Pi 框架会重新调用它获取最新工具列表。

## 五、专家模式（多智能体写作）设计

专家模式只在 **正文编写（`draft`）阶段** 生效，采用 **Coordinator + 多个 Section Writer 的串行多智能体架构**。

### 5.1 文件位置与角色

| 文件 | 角色 |
|------|------|
| `web/src/workspaces/short/expertDraft/ExpertDraftAiChat.tsx` | **Coordinator 智能体 UI 壳**：挂载总控 Agent，管理聊天面板的显示与切换。 |
| `web/src/workspaces/short/expertDraft/coordinatorTools.ts` | **Coordinator 工具**：`create_draft_sections`（创建正文列表）、`create_character_state_sections`（创建人物状态列表）、`start_expert_writing`（启动后台写作）。 |
| `web/src/workspaces/short/expertDraft/sectionWriter.ts` | **Section Writer 执行引擎**：串行创建/运行每个小节的独立 Agent。 |
| `web/src/workspaces/short/expertDraft/prompts.ts` | **专家模式提示词**：总控系统提示词 + 小节编写系统提示词 + 动态用户提示词。 |
| `web/src/workspaces/short/expertDraft/ExpertDraftEditor.tsx` | **左侧编辑器**：显示小节列表 + 人物状态列表的可视化界面。 |

### 5.2 设计原理

#### 总控智能体（Coordinator）

- **系统提示词**：`buildExpertDraftCoordinatorSystemPrompt()`
- **任务范围**：
  1. 根据已有大纲和设计内容，初始化专家模式的「正文小节列表」与「人物状态列表」。
  2. 当用户确认开始后，调用 `start_expert_writing` 启动后台小节编写。
- **可读上下文**：全书 8 个阶段的已保存内容 + 当前专家正文/人物状态列表。
- **约束**：必须使用工具修改左侧编辑器，不要只在聊天里输出列表；不要调用普通模式工具。

#### 后台小节编写智能体（Section Writer）

- **系统提示词**：`buildSectionWriterSystemPrompt()`
- **运行机制**：
  - 每小节创建一个独立 `Agent` 实例
  - **严格串行**执行：写完第 N 节，再写第 N+1 节
  - 每个 Agent 的 `sessionId` 包含小节 ID，确保会话隔离
- **专属工具**（每个小节仅两个）：
  - `write_section_body` —— 覆盖当前小节正文框
  - `write_character_state` —— 覆盖当前小节人物状态框
- **动态用户提示词**：`buildSectionWriterUserPrompt()` 注入：
  - 全书小节顺序列表
  - `character_design` / `intro_design` / `plot_design` / `plot_refine` / `outline` 全文
  - 上一小节结束时的人物状态
  - 前面已写小节的完整正文（用于保持连贯性）
  - 当前小节已有草稿（支持续写/改写）

#### UI 切换逻辑

- 平时右侧显示 **Coordinator** 聊天面板
- 当 `start_expert_writing` 启动后，每写一个小节，右侧聊天面板**临时切换**到该小节的 **Section Writer Agent**
- 写完一小节后自动切回 Coordinator，直到所有小节完成

### 5.3 状态流转

```
[Coordinator 初始化列表]
         ↓
[用户确认 / AI 调用 start_expert_writing]
         ↓
[创建 AbortController]
         ↓
[for 每个 sectionId] ──→ [创建 Section Writer Agent]
                            ↓
                     [运行 Agent：写正文 + 写人物状态]
                            ↓
                     [Agent 结束，切回 Coordinator]
                            ↓
                     [继续下一个 sectionId]
         ↓
[全部完成 / 用户中断] ──→ [running=false, active_section_id='']
```
